# Grapefruit Music & Podcasts 4.1 beta 6 — build 44

## Podcast time running out early

Reported on beta 5: the remaining time reached 0:00 about two minutes before the end, and the
elapsed time kept going (streamed and downloaded episodes). Android's MP3 reader (used by both
MediaPlayer and Grapefruit's own engine) takes an MP3's length from its "Info" header when it has
one. Podcast hosts that insert ads as an episode is served keep the episode's header, whose frame
count leaves the ads out: the length comes out short by the ads. For a constant-bitrate MP3 (which
an Info header means) the position and seeking still go by bytes and stay right; only the length
was wrong.

`Mp3Length` (pure Java) now works it out from the audio:
- Downloaded episodes: every frame header in the file (in the background, once per file per run),
  skipping ID3 tags (cover art), the Info/Xing frame and an ID3v1 tag at the end; exact also when
  the bitrate changes (ads at another bitrate).
- Streamed episodes: the relay keeps the start of the stream it passes to the player (up to 1MB,
  past a large ID3 tag) and the size from the response; for a constant bitrate the length is the
  audio's bytes over the bitrate. A variable-bitrate (Xing/VBRI) header is left to the decoder.
- `Engine.setLength` gives it to MediaPlayer's and Grapefruit's engines (and to Live Mode's end
  detection).

Checked on real encoder output: a 60 s LAME CBR file with 30 s spliced on after its Info header
(as ad insertion does) decodes to 90.07 s; the full scan and the stream estimate both give 90,070 ms
(the header says 60 s). New `Mp3LengthTest` (8 tests): stale Info header with ads, a 200KB tag
still arriving, Xing left alone, no header, not an MP3, a file with a 300KB tag, two bitrates and
an ID3v1 tag, header parsing.

## Name, logo, splash screen, typeface

- `app_name` "Grapefruit Music & Podcasts"; the launcher entries (one per theme icon) are
  "Grapefruit". About, Settings and the radio report use the new name. The F-Droid listing's name
  (fastlane title, repo name, the repo's web page) changes with the next stable release, so the
  F-Droid repository isn't touched by a beta.
- `docs/brand`: SVG logos from `tools/brand/logo.py`: the Telegram channel's grapefruit as vectors,
  masked round, and "Grapefruit Music & Podcasts" in Geist Pixel's Triangle shape (its variable
  font's Element Shape axis, ELSH, at 60: the named instance "Triangle"; Geist Pixel also ships it as
  GeistPixel-Triangle, whose outlines are used once checked to match). The lettering is outlines,
  each glyph defined once: 30KB per file, no font needed.
- Splash screen: the stacked logo (grapefruit, "Grapefruit", "Music & Podcasts") as PNGs at each
  density (Android 4.2 has no vector drawables; pngquant, 297KB in all), on each theme's
  background (`splash_*` layer-lists), as each theme's window background and as a view over the
  app for 800ms (500ms after Android 12's own splash) when it starts, fading out. Android starts
  the app in `Theme.Grapefruit.Launch` (Grapefruit Dark); Android 12+ shows its splash with the
  round grapefruit, and Android 13+ is told the picked theme's splash colours for next time. The
  window background is dropped after the splash so it isn't drawn under every page.
- Typeface: Geist (Regular, Medium, SemiBold, Bold; static TTFs from assets, which Android 4.2
  loads) through `Fonts`: Regular for text, SemiBold for bold text, Bold for bold text 26sp and
  up, Medium for the tab bar and small labels; applied in Ui.text and fields, the main layout, the
  few views made elsewhere, and text drawn on canvases (equalizer, dial, Karaoke and Live slider,
  fast-scroll letter, station artwork). Notifications keep Android's font (their views can't load
  one). Credited in About; OFL text in `assets/fonts/Geist-OFL.txt`.
