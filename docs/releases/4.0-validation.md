# Grapefruit Music 4.0 stable (37)

Changes since beta 4:

- Icon-only player actions are Lyrics, Karaoke, Shuffle, Repeat, Queue.
- Playback paths are drawn at destination pixel dimensions instead of scaling a small hardware path and its outline.
- Settings/navigation disclosure arrows have a dedicated theme colour. Contrast against control, pressed control, surface and background respectively: Light 4.38/3.61/5.07/5.07; Dark 6.30/5.13/7.69/9.50; Grapefruit Light 4.95/4.11/6.19/5.89; Grapefruit Dark 6.87/5.82/8.04/8.90.
- Karaoke strength occupies a separate 48dp column with a 12dp trailing margin. The weighted artwork area measures the remaining width, so the slider cannot overlap it. Height is capped at 240dp and fits shorter stages. Hiding karaoke returns the space; lyrics/queue hide the artwork row. Removed ineffective artwork-margin adjustment (PlayerMetadata positions its children itself).
- Stable versionName 4.0, versionCode 37. Updated F-Droid listing and Telegram changelog.

Validation:

- JDK 21, offline Gradle: assembleDebug, assembleRelease, testDebugUnitTest, lintDebug passed.
- 139 unit tests passed, zero errors/failures. Android lint: zero errors.
- Four Pages renderer tests passed.
- XML action order and separate slider/artwork parentage verified; theme contrast calculated from committed palette values.
- applicationId unchanged; minSdk 17, targetSdk 36. Production workflows unchanged. Existing workflow names the signed release asset grapefruit-music-4.0.apk and pins the permanent certificate.
- Existing public F-Droid index signer SHA-256 recorded before publishing: 33AAF333079D68BD79F59463B59E33585E4EF7CB4E9F6722CE1F1281F93940F4.

These are build, host-test and source/layout checks, not physical-device UI verification. Earlier beta validation and karaoke evaluation limitations remain in docs/beta-3-validation.md and docs/beta-4-validation.md.
