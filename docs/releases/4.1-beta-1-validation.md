# Grapefruit Music 4.1 beta 1 — build 39

Base: published 4.0.1 commit ec8224fa3e14d49e575cda380b724a00be910ba7.

Live Mode adds eight delayed, gently detuned copies of estimated song vocals, a small
stereo venue, and a procedural audience/applause bed shaped by a newly fitted AR-12
statistical model. It is a stylized live simulation, not a generative singing model.
Original song lyrics supply singalong; instrumental inputs receive venue/audience
ambience, with possible instrument leakage from the separator. Karaoke and Live Mode
have independent persisted 0–100% controls. Both use one shared vocal-separator pass.
Switches crossfade, amount changes glide, and seek/reset clears audience history.

The new crowd model uses 24 original two-second procedural clips for training (48 s)
and eight disjoint held-out clips (16 s); no real crowd recordings or pretrained crowd
weights were used. Source, generated-data seeds, licenses, model/recipe hashes and
metrics are in tools/live and assets/live_training.json. GPL-3.0-or-later applies to
the new code, data and model. Existing CC BY 4.0 SiSEC18-MUS separator attribution is
retained in the app. Held-out normalized AR prediction error is 0.22856 versus 0.24852
on training clips. These are synthetic prediction metrics, not perceptual evidence.

Now Playing action order is Lyrics, Karaoke, Live, Shuffle, Repeat, Up Next. All six
have labels, the original raised-hands line glyph uses theme tint, and the row is
60dp tall with 12dp separation from the volume row. Two independent 48dp slider
columns reserve space beside artwork and fit the stage height. Radio layouts keep
their existing navigation semantics; FM hides music actions.

Validation:

- JDK 21 offline Gradle: assembleDebug, assembleRelease, testDebugUnitTest, lintDebug passed.
- 154 unit tests passed, zero errors/failures. Ten new tests cover zero-strength
  transparency relative to the delayed dry path, silence, multiple sample rates,
  singalong from the vocal input, granular strength, tail decay, chunk invariance,
  limiter bounds, seek reset, and simultaneous Karaoke/Live/Mono processing.
- Fixed separator initialization on format/reset so a fresh engine and a reset
  engine start in the same requested effect state, without an initial dry burst.
- Static XML check confirms exactly six music actions in the requested order and
  the explicit row spacing. UI checks are source-based; no device/emulator is attached.
- Host JVM under a 48 MB heap processed 20 seconds of stereo audio in 1.04–1.36 seconds
  across three rounds including the separator, live mix and limiter; latency was
  3248 frames at 44.1 kHz (separator plus lookahead). This is not an Android benchmark.
- APK package remains io.github.hayliewordsman.grapefruitmusic; version 4.1-beta-1 (39),
  minSdk 17, target/compile SDK 36. No new Android runtime dependencies, database
  migration, signing configuration changes, or production workflow changes.

Publication uses the existing Build APK workflow on codex/grapefruit-v4.1-beta-1.
The beta is distributed as its GitHub Actions artifact archive, without a GitHub
release or default-branch push. The F-Droid workflow's default-branch guard prevents
publication for this branch. Hardware listening, realistic crowd quality, narrow/
large-font layouts, and actual Jelly Bean throughput remain unverified.
