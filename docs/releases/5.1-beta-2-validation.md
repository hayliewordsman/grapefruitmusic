  Next take the whole left column (np_stage, 44%): the mini header (small artwork, title, artist)

- Rendered with a temporary Robolectric test (not committed), song lyrics from the lyrics cache:

## The playing notification (Android 4.2, JP5S)

- 5.0's notification sometimes showed only the icon and "Grapefruit". That is the placeholder
  posted as the service starts; the full notification posted right after can be dropped by Android
  4.x without an error when the call carrying it is too big (RemoteViews carry their bitmaps).
- buildNotification now gives each view its own cover at the size it's shown (64dp folded, 128dp
  unfolded), at most 256 px, RGB_565 when opaque (fittedArt(sizeDp), cached per size); button
  bitmaps are at most 72 px. Measured with the temporary test (1024 px opaque cover):
  hdpi 162 KB (was 360 KB), xhdpi 288 KB (was 640 KB), xxhdpi 362 KB (was 1440 KB) of pictures.
  The lock-screen copy of the artwork is RGB_565 when opaque.
- The first notification (onStartCommand's startForeground) now has the song's title and artist
  (or the station), so if the full one were ever lost it still says what's playing.

## Add Songs: a whole album

- Reported: adding a whole album to a playlist with Add Songs closed the app; no crash report.
  Not reproducible here: a temporary Robolectric test drove Add Songs with a stand-in source and
  with the real LocalSource over a stand-in MediaStore (SQLite): a new playlist, two whole albums
  (24 songs), saved in order; songs removed and another album added (34); ✓ taking an album back;
  an album opened in the sheet. A library fault while saving shows "Couldn't Save Changes".
- Every save and load already ran in the background with errors shown, so a Java exception there
  would not close the app, and one on the main thread would have left a crash report. Without a
  report, the likeliest cause is Android ending the app: a ContentResolver call or open cursor holds
  the media provider stably, and if android.process.media dies (low memory, a firmware fault) the
  client app is killed with it.
- LocalSource now reaches MediaStore through MediaLibrary: unstable ContentProviderClients (API 16)
  for queries (released when the cursor closes), insert, bulkInsert, update and delete. If the
  library dies, the call fails with "This phone's media library stopped" and Grapefruit carries on.
- CrashReport keeps 96 KB in reserve, freed before writing, and falls back to a short report (the
  exception and 12 frames) if the full one can't be written, so a crash for want of memory still
  leaves a report. Notes (no names) for Add Songs adding an album and for playlist saves.
