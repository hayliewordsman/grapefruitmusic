# Grapefruit Music 4.1 beta 3 — build 41

Keeps Live Mode's venue echoes and singalong effect, adds distinct stadium cheering
at song boundaries, and softens the excessive percussion echoes reported in beta 2.

- A three-second opening crowd overlaps the song's start. A different three-second
  closing crowd plays after the final decoded note, before advancing the queue.
  EOF triggers closing even when duration is unknown. These independent cheers
  remain audible over quiet/silent music; Live strength, master volume, Mono Audio
  and the final limiter apply. Pausing pauses playback, skipping discards the tail,
  and seeking/resuming beyond the opening window does not restart an intro.
- Original procedural synthesis: 96 open-vowel whoops, 180 claps, nine gliding
  whistles and short baked stereo reflections per event. No human recordings,
  libraries, pretrained weights or new model training. GPL-3.0-or-later source,
  generated audio and manifests are committed. `tools/live/render_stadium.py`
  regenerates both takes with seeds 7101/7102; hashes are in stadium_cheers.json.
- Bundled PCM is 144,012 bytes for two three-second stereo takes at 12kHz/8-bit.
  It is loaded once on the decoder thread. Playback is interpolation/mixing only;
  end audio uses bounded 1024-frame blocks, not a large processed tail allocation.
- Lower room/ensemble gains plus a smoothed transient-sensitive send soften sharp
  percussion repeats. Original percussion is unaffected. The controlled 2ms burst
  test measured echo-tail energy at 7.1% of beta 2 (~11.5dB lower); real-song
  subjective balance remains to be tested. Generated stadium cheers are separate.

Validation includes regression tests for independent opening/closing cheers,
absence before timeline initialization/after the event, seeks and Live toggles,
zero strength, bounded stereo output at 8/22.05/44.1/48/96kHz, existing limiter and
mono behavior, coexistence with ambience, and preserved dry percussion attacks.
Host checks under a 48MB Java heap process a 20-second song plus three-second
closing cheer in 0.15–0.50s across three rounds (build was active concurrently).
This is not a JP5S/Dalvik benchmark or human listening test.

The APK remains io.github.hayliewordsman.grapefruitmusic, minSdk 17, target/compile
SDK 36, version 4.1-beta-3 (41). No runtime dependencies, signing configuration or
production workflow changes. Publish only the beta branch's existing Build APK
artifact archive. No default-branch push, release or F-Droid deployment.

UI correction: removed the old inline Karaoke/Live artwork columns and their
listeners. Each effect now has only its percentage popup, opened on enable or
long-press. Separate saved strengths and simultaneous effects remain. Artwork no
longer reserves space for duplicate sliders. Source/XML check verifies the removed
IDs are absent and the two action buttons route to their respective single popup.

Final local validation: JDK 21 offline assembleDebug, assembleRelease, all 164 unit
tests and lintDebug passed. APK badging confirms version 4.1-beta-3, code 41 and
minSdk 17. Cheer PCM and generator SHA-256 match the committed manifest.
