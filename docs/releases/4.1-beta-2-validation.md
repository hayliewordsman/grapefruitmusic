# Grapefruit Music 4.1 beta 2 — build 40

Addresses the report that Live Mode alone stuttered and added no audible crowd on
an Android 4.2.2 JP5S, while Karaoke worked normally; neither strength slider appeared.
No hardware log or on-device trace was available, so these source fixes target the
identified expensive/gated paths rather than establishing the exact device failure.

Changes:

- Live-only playback no longer loads, warms up or runs the vocal separator. Crowd
  and room mixing start with no separator model. A cheap filtered stereo-centre
  vocal-band estimate feeds four detuned delay voices. This approximation can
  include instruments; it is not isolated-vocal generation. When Karaoke is also
  enabled, its already-running separator's vocal estimate is reused.
- Pre-rendered the existing fitted GPL AR crowd model into a deterministic short
  texture table during export; removed per-sample AR inference, tanh, sin and
  long/double remainder from LiveAmbience. Float power-of-two delay rings replace
  the double/modulo rings. No steady-state LiveAmbience per-sample allocation.
- Raised audience texture gain and adjusted independent clap bursts. The limiter,
  silence-dependent crowd envelope and strength smoothing remain.
- Live-only latency is now the existing limiter lookahead (176 frames at 44.1kHz)
  instead of separator plus limiter (3248 frames). Karaoke keeps its own latency.
- Published separator model is volatile, so effect changes do not wait on its
  synchronized background warm-up lock. Karaoke's separation algorithm is unchanged.
- Enabling Karaoke or Live selects artwork and opens a full-width percentage control;
  long-pressing either action reopens it, including from Lyrics/Up Next. Inline
  percent sliders remain beside artwork. This also handles cramped display layouts.
- VersionName 4.1-beta-2, code 40. Package, minSdk 17, target/compile SDK 36, signing
  configuration, dependencies and GitHub workflows are unchanged.

Validation:

- JDK 21 offline Gradle debug/release builds, all 156 tests and lint passed before
  final packaging. Two added regressions require Live to start with no model and
  audibly change the output without separator latency, including activation during
  playback. Existing checks cover zero strength, silence, multiple rates, strength,
  tails, reset, limiter bounds, block invariance and Karaoke/Live/Mono interaction.
- Host JVM under a 48MB heap: 20 seconds Live-only processing in 0.068–0.129 seconds
  across four rounds, versus beta 1's previously recorded 1.04–1.36 seconds. This is
  a host throughput comparison, not a JP5S/Dalvik measurement.
- Training/export still uses original generated GPL data, disjoint evaluation seeds,
  and no downloaded recordings or pretrained crowd weights. Recipe, model and texture
  hashes and export seed 6101 are in assets/live_training.json; see tools/live/README.md.
- Device listening, slider screenshots and JP5S underrun behavior remain unverified.
  The user needs to confirm that this revised beta resolves their hardware symptoms.
